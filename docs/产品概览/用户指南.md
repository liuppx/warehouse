# Warehouse 用户指南

本文面向 Warehouse 普通用户、集成方和运维支持人员，说明如何使用 Web 页面、WebDAV、S3 和 Warehouse Tool 完成文件管理、客户端接入和验证。

如果你只关心部署、Nginx 或 active/standby，请看 [部署手册.md](../运维部署/部署手册.md)。如果你要看 JSON API 字段或 S3 技术边界，请看 [Warehouse OpenAPI](../应用集成/OpenAPI/接口契约说明.md) 与 [S3 设计方案](../应用集成/S3协议.md)。

如果你要让模型客户端或自动化程序访问 Warehouse，请直接阅读 [Skill 使用](#5-skill-使用)；普通文件管理场景从第 2 节开始即可。

## 1. 基本概念

### 1.1 资产空间

Warehouse 当前把用户文件分成三个逻辑资产空间：

| 空间 | 用途 | WebDAV 路径 | S3 bucket |
| --- | --- | --- | --- |
| 个人存储 | 用户主动上传、整理和分享的文件 | `/dav/personal/...` | `personal` |
| 应用存储 | DApp、前端应用或 UCAN 场景产生的数据 | `/dav/apps/...` | `apps` |
| 服务存储 | 后台服务集成、定时任务或服务端自动化产生的数据 | `/dav/services/...` | `services` |

这三个空间不是三套存储。WebDAV 和 S3 只是两种访问协议，最终看到的是同一套用户文件。

### 1.2 WebDAV 凭证与 S3 凭证

| 凭证类型 | 用途 | 认证方式 | 是否可互用 |
| --- | --- | --- | --- |
| WebDAV 凭证 | Finder、Windows 网络位置、rclone WebDAV、davfs2、脚本上传 | Basic Auth，用户名是 `keyId`，密码是 `keySecret` | 不能用于 S3 |
| S3 凭证 | AWS CLI、rclone S3、MinIO Client、SDK | AWS Signature V4，Access Key ID + Secret | 不能用于 WebDAV |

所有密钥的 Secret 都只在创建时显示一次。关闭创建弹窗后无法找回，只能撤销旧凭证并重新创建。

### 1.3 权限含义

| 权限 | WebDAV 行为 | S3 行为 |
| --- | --- | --- |
| 读 / 下载 | 列目录、下载文件 | `ListBucket`、`HeadObject`、`GetObject` |
| 新建 / 上传 | 新建目录、上传新文件 | 上传新对象、创建 Multipart 上传 |
| 更新 / 重命名 | 覆盖、移动、重命名 | 覆盖已有对象 |
| 删除 | 删除文件或目录 | 删除对象 |

建议默认使用最小权限：只读任务只给读权限；备份任务通常给读、新建、更新；确实需要清理远端时再给删除权限。

## 2. Web 页面使用

### 2.1 登录与空间切换

1. 打开 Warehouse Web 地址，例如：`https://warehouse.tidukongjian.com/`。
2. 使用账号密码、钱包或站点启用的其他方式登录。
3. 在文件页面切换个人存储、应用存储或服务存储。
4. 进入目录后可以上传、下载、重命名、删除、创建目录和查看详情。

### 2.2 分享

Warehouse 支持两类分享：

- 公开分享：生成可访问链接，适合只读下载。
- 定向分享：分享给指定地址、分组或全员，可按权限允许下载、上传、重命名或删除。

分组分享按当前分组成员动态授权。分组成员变化后，不需要重新创建分享。

在「分享给我」页面中，具备读取权限的接收者可以为收到的单个文件或共享目录内的文件生成公开下载链接。派生链接不会复制文件，其有效期不会超过原定向分享；原分享被撤销、过期，或者接收者不再属于有效受众后，派生链接会同步失效。目录本身暂不生成公开下载链接。

资源分享与文件路径保持关联：

- 删除已分享的文件或目录时，对应定向分享、公开链接以及派生公开链接会一并失效。
- 移动或重命名资源时，分享会跟随新路径继续有效；移动目录时，其子文件的分享路径也会更新。
- 复制资源不会把原资源的分享关系复制到新副本。
- 从回收站恢复资源不会恢复删除前的分享，需要重新创建。

### 2.3 回收站

通过 Web 页面或 WebDAV 删除的文件会进入回收站。文件进入回收站后仍占用额度，只有永久删除或清空回收站后才释放额度。

注意：S3 删除遵循 S3 客户端预期，是永久删除，不进入 Warehouse 回收站。
无论通过 WebDAV、Web 页面还是 S3 删除资源，相关分享链接都会同步失效。

如果删除的是加密目录，目录下的 `.warehouse-crypto.json` 加密 marker 会随目录一起进入回收站。重新创建同名普通目录不会继承旧加密属性；Web 前端会在删除成功后清理当前页面会话里的同路径加密目录缓存。

### 2.4 密钥管理

进入「密钥管理」后可以看到以下 tab：

- `WebDAV 凭证`：用于 WebDAV 客户端。
- `S3 凭证`：用于 S3 兼容客户端。
- `Warehouse Tool`：用于 Chat、Agent 和 Skill 的受限资产调用。

生效中的凭证可以撤销。已撤销的凭证可以删除。删除只用于清理列表，不会恢复 Secret，也不会影响已经失效的访问能力。

## 3. WebDAV 凭证使用

### 3.1 什么时候选 WebDAV

适合这些场景：

- 用系统文件管理器挂载网络盘。
- 用 rclone、davfs2 或 curl 做文件同步。
- 希望删除进入 Warehouse 回收站。
- 需要访问分享、目录树和常规文件管理语义。

### 3.2 创建 WebDAV 凭证并选择目录

1. 打开「密钥管理」。
2. 切到 `WebDAV 凭证`。
3. 点击「新建」。
4. 点击「选择目录」，在弹窗中切换个人、应用或服务资产空间，并逐级进入子目录；面包屑可以返回任意上级目录。到达目标位置后点击「选择当前目录」，不需要手写路径。
5. 填写密钥名称、权限和有效期。
6. 创建成功后立即保存 `Key ID` 和 `Key Secret`。创建操作已经同时完成首次目录绑定，密钥可以立即使用。

建议把目录范围收窄到具体业务目录，例如 `/personal/backups`，不要默认给整个 `/personal`。如需让同一密钥访问另一个目录，后续仍可在目标目录的「授权密钥」中追加绑定。

### 3.3 连接信息

请向站点管理员确认以下地址：

```bash
export WAREHOUSE_WEBDAV_URL="https://warehouse.tidukongjian.com/dav/"
export WEBDAV_KEY_ID="ak_xxxxxxxxxxxxxxxx"
export WEBDAV_KEY_SECRET="sk_xxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxx"
```

WebDAV URL 一般是站点域名后加 `/dav/`。如果站点配置了其他 `webdav.prefix`，以管理员提供的地址为准。

### 3.4 curl 验证

列出个人存储根目录：

```bash
curl -i \
  -u "$WEBDAV_KEY_ID:$WEBDAV_KEY_SECRET" \
  -X PROPFIND \
  -H "Depth: 1" \
  "${WAREHOUSE_WEBDAV_URL}personal/"
```

预期结果：HTTP 状态为 `207 Multi-Status`，响应中能看到目录项。

上传并下载一个测试文件：

```bash
printf 'hello warehouse\n' > /tmp/warehouse-webdav-test.txt

curl -i \
  -u "$WEBDAV_KEY_ID:$WEBDAV_KEY_SECRET" \
  -T /tmp/warehouse-webdav-test.txt \
  "${WAREHOUSE_WEBDAV_URL}personal/warehouse-webdav-test.txt"

curl \
  -u "$WEBDAV_KEY_ID:$WEBDAV_KEY_SECRET" \
  "${WAREHOUSE_WEBDAV_URL}personal/warehouse-webdav-test.txt"
```

预期结果：上传返回 `201 Created` 或 `204 No Content`，下载输出 `hello warehouse`。

### 3.5 rclone WebDAV 配置

推荐使用交互式配置，避免把明文 Secret 写入配置文件：

```bash
rclone config
```

按提示选择：

```text
n) New remote
name> warehouse-webdav
Storage> webdav
url> https://warehouse.tidukongjian.com/dav/
vendor> other
user> ak_xxxxxxxxxxxxxxxx
password> sk_xxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxx
```

验证：

```bash
rclone lsd warehouse-webdav:
rclone lsf warehouse-webdav:personal
rclone copy /tmp/warehouse-webdav-test.txt warehouse-webdav:personal/
rclone cat warehouse-webdav:personal/warehouse-webdav-test.txt
```

### 3.6 davfs2 挂载

Linux 可以使用 davfs2 挂载为本地目录：

```bash
mkdir -p ~/warehouse
sudo mount -t davfs "$WAREHOUSE_WEBDAV_URL" ~/warehouse
```

建议把凭证写入 `~/.davfs2/secrets` 或系统级 secrets 文件，避免命令行泄露：

```text
https://warehouse.tidukongjian.com/dav/ ak_xxxxxxxxxxxxxxxx sk_xxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxx
```

如果挂载后要像本地目录一样拖拽、覆盖或重命名文件，建议 WebDAV 凭证至少具备读、新建、更新权限。只允许新增且不覆盖的自动化任务，可以只给读、新建。

## 4. S3 凭证使用

### 4.1 什么时候选 S3

适合这些场景：

- 使用 AWS CLI、rclone S3、MinIO Client 或 S3 SDK。
- 做对象式上传、下载、同步和备份。
- 希望工具按 S3 语义处理大文件或对象列表。

当前 S3 是协议兼容层，不是把底层存储迁移到了 AWS S3 或 MinIO。S3 客户端看到的 bucket 是 Warehouse 的逻辑资产空间。

### 4.2 创建 S3 凭证

1. 打开「密钥管理」。
2. 切到 `S3 凭证`。
3. 点击「新建」。
4. 选择逻辑 bucket：`personal`、`apps` 或 `services`。
5. 填写 bucket 下目录，留空表示授权整个 bucket。
6. 创建成功后立即保存 `Access Key ID` 和 `Secret`。

示例：

| 选择 | bucket 下目录 | 实际授权范围 | S3 客户端写法 |
| --- | --- | --- | --- |
| `personal` | 留空 | `/personal` | `s3://personal/...` |
| `personal` | `backup` | `/personal/backup` | `s3://personal/backup/...` |
| `apps` | `demo/data` | `/apps/demo/data` | `s3://apps/demo/data/...` |
| `services` | `reporting/daily` | `/services/reporting/daily` | `s3://services/reporting/daily/...` |

#### 目录范围与 S3 标准的关系

S3 没有真实的目录，客户端中看到的目录是 Object Key 的前缀（prefix）。例如 `personal` bucket 中的 `backup/photos/a.jpg` 是一个完整的 Object Key，`backup/` 只是它的前缀。

Warehouse 创建凭证时显示的 `rootPath` 是服务端权限范围，不是 S3 标准凭证字段，第三方客户端不需要识别或传递该字段。Warehouse 会对标准 S3 请求中的 bucket 和 Object Key 进行服务端权限检查。

例如凭证的授权范围是 `/personal/backup`：

- 第三方客户端的 bucket 填 `personal`。
- 路径或 prefix 填 `backup/`。
- `backup/report.zip` 可以访问。
- `private/report.zip` 会返回标准 S3 `AccessDenied`。
- 客户端看到的对象名仍是 `backup/report.zip`，Warehouse 不会把 `backup/` 自动剥离成虚拟根目录。

这种“服务端将 Access Key 限制到 bucket 的某个 key prefix”的做法不需要改造 AWS Signature V4，AWS CLI、rclone、MinIO Client 和常见 S3 SDK 均可使用。但如果某个第三方应用只能配置 bucket、不能配置路径或 prefix，则应为它创建授权整个 bucket 的凭证。

### 4.3 连接信息

请向站点管理员确认 S3 Endpoint 和 Region：

```bash
export WAREHOUSE_S3_ENDPOINT="https://s3.tidukongjian.com"
export WAREHOUSE_S3_REGION="us-east-1"
export S3_ACCESS_KEY_ID="AKxxxxxxxxxxxxxxxx"
export S3_SECRET_ACCESS_KEY="xxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxx"
```

Warehouse S3 当前推荐 path-style 访问，也就是对象地址形如 `https://s3.tidukongjian.com/personal/path/to/file.txt`。

将 Warehouse 页面中的凭证信息填入第三方客户端时，按下表对应：

| 连接项 | 填写内容 | 说明 |
| --- | --- | --- |
| Endpoint | 管理员提供的 S3 Endpoint | `https://s3.tidukongjian.com` |
| Region | 管理员提供的 Region | 必须参与 Signature V4 签名 |
| Access Key ID | 创建结果中的 `Access Key ID` | 标准 S3 认证参数 |
| Secret Access Key | 创建结果中的 `Secret` | 只显示一次 |
| Bucket | `rootPath` 的第一段 | `/personal/backup` 对应 `personal` |
| Prefix/路径 | `rootPath` 扣除 bucket 后的部分 | `/personal/backup` 对应 `backup/` |

`rootPath` 仅用于 Warehouse 凭证管理和权限表达，不应当作 Endpoint、bucket 名或额外 HTTP 请求头填入 S3 客户端。

### 4.4 AWS CLI 配置与验证

配置环境变量：

```bash
export AWS_ACCESS_KEY_ID="$S3_ACCESS_KEY_ID"
export AWS_SECRET_ACCESS_KEY="$S3_SECRET_ACCESS_KEY"
export AWS_DEFAULT_REGION="$WAREHOUSE_S3_REGION"
```

建议使用独立 profile，并开启 path-style：

```bash
aws configure set profile.warehouse.region "$WAREHOUSE_S3_REGION"
aws configure set profile.warehouse.s3.addressing_style path
```

列 bucket 和对象：

```bash
aws --profile warehouse --endpoint-url "$WAREHOUSE_S3_ENDPOINT" s3 ls
aws --profile warehouse --endpoint-url "$WAREHOUSE_S3_ENDPOINT" s3 ls s3://personal/
```

如果凭证只授权 `/personal/backup`，列举、上传和下载时都应使用 `backup/` 前缀：

```bash
aws --profile warehouse --endpoint-url "$WAREHOUSE_S3_ENDPOINT" \
  s3 ls s3://personal/backup/

aws --profile warehouse --endpoint-url "$WAREHOUSE_S3_ENDPOINT" \
  s3 cp /tmp/warehouse-s3-test.txt s3://personal/backup/warehouse-s3-test.txt
```

上传、下载、校验：

```bash
printf 'hello warehouse s3\n' > /tmp/warehouse-s3-test.txt

aws --profile warehouse --endpoint-url "$WAREHOUSE_S3_ENDPOINT" \
  s3 cp /tmp/warehouse-s3-test.txt s3://personal/warehouse-s3-test.txt

aws --profile warehouse --endpoint-url "$WAREHOUSE_S3_ENDPOINT" \
  s3 cp s3://personal/warehouse-s3-test.txt /tmp/warehouse-s3-downloaded.txt

diff /tmp/warehouse-s3-test.txt /tmp/warehouse-s3-downloaded.txt
```

预期结果：`diff` 无输出，表示上传和下载内容一致。

删除测试对象：

```bash
aws --profile warehouse --endpoint-url "$WAREHOUSE_S3_ENDPOINT" \
  s3 rm s3://personal/warehouse-s3-test.txt
```

注意：S3 删除是永久删除，不进入 Warehouse 回收站。

### 4.5 rclone S3 配置与验证

可以通过 `rclone config` 交互式创建，也可以写入配置文件。示例配置：

```ini
[warehouse-s3]
type = s3
provider = Other
env_auth = false
access_key_id = AKxxxxxxxxxxxxxxxx
secret_access_key = xxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxx
endpoint = https://s3.tidukongjian.com
region = us-east-1
force_path_style = true
```

验证：

```bash
rclone lsd warehouse-s3:
rclone lsf warehouse-s3:personal
rclone copy /tmp/warehouse-s3-test.txt warehouse-s3:personal/
rclone cat warehouse-s3:personal/warehouse-s3-test.txt
```

如果你的 S3 凭证只授权 `/personal/backup`，命令应写到该前缀下：

```bash
rclone lsf warehouse-s3:personal/backup/
rclone copy /tmp/warehouse-s3-test.txt warehouse-s3:personal/backup/
```

### 4.6 MinIO Client 配置与验证

MinIO Client 的命令名通常是 `mc`：

```bash
mc alias set warehouse \
  "$WAREHOUSE_S3_ENDPOINT" \
  "$S3_ACCESS_KEY_ID" \
  "$S3_SECRET_ACCESS_KEY" \
  --api S3v4 \
  --path on
```

验证：

```bash
mc ls warehouse/personal
mc cp /tmp/warehouse-s3-test.txt warehouse/personal/warehouse-s3-test.txt
mc cat warehouse/personal/warehouse-s3-test.txt
mc rm warehouse/personal/warehouse-s3-test.txt
```

如果凭证只授权 `/personal/backup`，对应命令是：

```bash
mc ls warehouse/personal/backup/
mc cp /tmp/warehouse-s3-test.txt warehouse/personal/backup/warehouse-s3-test.txt
```

### 4.7 S3 能力边界

当前 S3 兼容层适合常见上传、下载、列举、覆盖和删除。需要注意：

- bucket 当前固定为 `personal`、`apps` 和 `services`，不能任意创建新 bucket。
- S3 凭证只能访问创建时选择的 bucket 和目录前缀。
- 目录范围是服务端对 Object Key prefix 的授权限制，不是需要第三方客户端识别的自定义 S3 协议字段。
- 仅支持填写 bucket、不支持路径或 prefix 的第三方应用，建议使用授权整个 bucket 的凭证。
- S3 凭证不访问“分享给我的”目录。
- S3 删除是永久删除，不进入回收站。
- S3 客户端和 WebDAV 客户端可以看到同一份 `personal/apps/services` 数据，但两类凭证不能互用。

## 5. Skill 使用

### 5.1 获取 Skill

Warehouse 的通用 Skill 是 [`community-warehouse-skill`](https://github.com/yeying-community/marketplace/tree/main/skills/codex/community-warehouse-skill)，维护在 [yeying-community/marketplace](https://github.com/yeying-community/marketplace) 仓库的 `skills/codex` 目录下。也可以使用 [SSH 克隆地址](ssh://git@github.com/yeying-community/marketplace.git)：

```text
git@github.com:yeying-community/marketplace.git
```

可以使用 Git 获取仓库：

```bash
git clone git@github.com:yeying-community/marketplace.git
```

不同模型客户端的 Skill 安装位置和加载方式可能不同。安装时只需要将仓库中的 `skills/codex/community-warehouse-skill` 作为 Skill 目录交给客户端；不要把 Warehouse 的 WebDAV 或 S3 凭证写入 Skill 文件。本文后面的命令行示例使用 `WAREHOUSE_SKILL_DIR` 表示实际安装目录。

### 5.2 Skill 能做什么

Warehouse 提供通用的 `community-warehouse-skill`，让支持 Skill 的 Codex、Claude 或其他 Agent 通过统一的 Warehouse Tool 访问资产。它不是新的存储协议，也不会绕过 Warehouse 的用户、路径、UCAN、配额和审计校验。

当前 Skill 支持：

| 能力 | 说明 |
| --- | --- |
| 列出资产空间 | 查看 `personal`、`apps`、`services` |
| 列出对象 | 按路径查看目录和对象 |
| 查看元数据 | 获取大小、类型、ETag、checksum 和修改时间 |
| 读取对象 | 在授权范围内读取小对象 |
| 写入对象 | 使用 `warehouse.object.put` 创建或条件覆盖不超过 5 MiB 的文本、JSON 或二进制对象 |
| 上传本地文件 | 使用 `put-file` 将不超过 5 MiB 的本地文件写入授权路径 |

Skill 当前不提供删除对象、复制对象和大文件分片上传能力。需要这些操作时，请使用 Web 页面、WebDAV、S3 或对应的正式 API。这里的 Tool 是具体的 Warehouse 业务能力，MCP 只是可选的发现和调用协议；当前 Warehouse 提供的是 HTTP Tool 入口，不需要额外配置 MCP，也不能把它理解为已经提供独立 MCP Server。

### 5.3 配置 Skill

使用 Skill 前，需要先在 Warehouse 页面创建 `Warehouse Tool 凭证`，限定授权路径、允许动作和过期时间。安装 Skill 不会自动登录，也不会自动获得 Warehouse 权限。

建议按以下顺序准备：

1. 打开「密钥管理」中的 `Warehouse Tool` 标签，点击「新建」。
2. 填写凭证名称，在「授权目录」中点击「选择」并选定一个目录；授权会覆盖该目录及其子目录。
3. 选择 `asset:read`、`asset:write` 等实际需要的 Tool 权限，并设置过期时间。
4. 创建后立即保存只显示一次的凭证 Secret；遗失后只能撤销并重新创建。
5. 按下面任一种方式配置服务地址、凭证和默认上传目录。

`YEYING_WAREHOUSE_UPLOAD_DIRECTORY` 只指定 `put-file` 的默认远端目录，不是本地目录，也不会扩大凭证已有的授权范围。

可以通过环境变量配置：

```bash
export YEYING_WAREHOUSE_URL="https://warehouse.tidukongjian.com"
export YEYING_WAREHOUSE_TOOL_TOKEN="<短期 scoped Tool credential>"
export YEYING_WAREHOUSE_UPLOAD_DIRECTORY="/personal/backups"
```

也可以使用统一配置文件 `~/.yeying/skills/warehouse/config.toml`，将下面的内容保存到该路径：

```toml
[warehouse]
url = "https://warehouse.tidukongjian.com"
tool_token = "<短期 scoped Tool credential>"
upload_directory = "/personal/backups"
```

配置文件应只允许当前用户读写：

```bash
mkdir -p ~/.yeying/skills/warehouse
touch ~/.yeying/skills/warehouse/config.toml
chmod 600 ~/.yeying/skills/warehouse/config.toml
```

配置优先级为：

```text
命令行 --config > YEYING_WAREHOUSE_CONFIG > ~/.yeying/skills/warehouse/config.toml
```

环境变量会覆盖配置文件中的同名字段。`upload_directory` 是远端 Warehouse 目录，不是本地目录；执行 `put-file` 时，如果没有显式指定目标路径，Skill 会把本地文件名追加到这个目录。

### 5.4 首次验证

先用只读命令确认地址、凭证和授权范围都正确：

```bash
export WAREHOUSE_SKILL_DIR="$HOME/.codex/skills/community-warehouse-skill"

python3 "$WAREHOUSE_SKILL_DIR/scripts/warehouse_tool.py" catalog
python3 "$WAREHOUSE_SKILL_DIR/scripts/warehouse_tool.py" list /personal/backups
```

`catalog` 能返回 Tool 列表且 `list` 返回 `200`，说明 Skill 已加载、凭证有效，并且当前凭证至少有目标目录的读取权限。若返回 `401` 或 `403`，优先检查凭证是否过期、是否被撤销以及路径和动作范围；不要直接改用 WebDAV 或 S3 Secret 充当 Tool 凭证。

### 5.5 使用示例

如果宿主已经加载 `community-warehouse-skill`，可以直接提出类似请求：

- “列出 `/personal/backups` 下的文件。”
- “读取 `/personal/reviews/report.md`。”
- “把 `/tmp/result.json` 上传到 `/personal/reviews/result.json`。”
- “查看 `/apps/<app-id>/manifest.json` 的元数据。”

需要脚本化调用时，可以使用 Skill 附带的无依赖命令行客户端。将 `WAREHOUSE_SKILL_DIR` 替换为 Skill 的实际安装目录：

```bash
export WAREHOUSE_SKILL_DIR="$HOME/.codex/skills/community-warehouse-skill"

python3 "$WAREHOUSE_SKILL_DIR/scripts/warehouse_tool.py" stat /personal/backups/result.json
python3 "$WAREHOUSE_SKILL_DIR/scripts/warehouse_tool.py" read /personal/backups/result.json
python3 "$WAREHOUSE_SKILL_DIR/scripts/warehouse_tool.py" put \
  /personal/reviews/note.md \
  "# Review\n\n审查结论"
python3 "$WAREHOUSE_SKILL_DIR/scripts/warehouse_tool.py" put-file \
  /tmp/result.json \
  /personal/reviews/result.json
```

`put-file` 会根据本地文件内容计算 SHA-256，并默认使用 base64 编码传输。默认只创建对象；覆盖已有对象必须显式使用 `--overwrite`，需要并发保护时使用 `--if-match`。

### 5.6 权限与安全边界

- `YEYING_WAREHOUSE_TOOL_TOKEN` 是 Warehouse Tool 凭证，不是 WebDAV `keyId/keySecret`，也不是 S3 Access Key/Secret，三者不能互换。
- 每次 Skill 调用都会由 Warehouse 重新校验身份、授权路径、动作、UCAN app scope、配额和 checksum。
- Tool 凭证应使用短期、可撤销、最小路径范围的凭证，不要把用户主密码、钱包私钥或管理员密钥交给 Skill。
- 不要直接上传包含密码、Token、私钥的 `.zshrc`、配置文件或日志；上传现场材料前应先检查并脱敏。
- Skill 只处理调用方明确要求写入的对象，不会自动读取隐藏提示词、模型内部推理或完整客户端会话。需要将某个 Project 任务的执行过程归档，应使用独立的 `community-project-skill`。

Skill 的调用结果由 Warehouse 负责审计；调用方应保留返回的 `requestId`、`traceId`、路径和 checksum，便于事后核查。详细 Tool 契约见 [资产 Tool 契约](../应用集成/资产Tool契约.md)，凭证规则见 [Tool 凭证与授权方案](../应用集成/Tool凭证与授权方案.md)。

## 6. 客户端选择建议

| 场景 | 推荐协议 | 推荐客户端 |
| --- | --- | --- |
| 日常网页上传下载 | Web 页面 | 浏览器 |
| 桌面文件管理器挂载 | WebDAV | macOS Finder、Windows 网络位置、davfs2、支持 WebDAV 的 GUI 客户端 |
| 自动化同步和备份 | WebDAV 或 S3 | rclone |
| S3 工具链或对象式备份 | S3 | AWS CLI、MinIO Client、rclone S3、AWS SDK |
| 希望删除后可从回收站恢复 | WebDAV 或 Web 页面 | 浏览器、WebDAV 客户端 |
| 希望按 S3 客户端语义永久删除 | S3 | AWS CLI、mc、rclone S3 |

选择原则：

- 普通用户优先用 Web 页面。
- 桌面挂载优先用 WebDAV。
- 自动化任务优先用独立凭证，不使用主账号密码。
- 已经使用 S3 工具链的备份、同步或 SDK 集成，使用 S3 凭证。

## 7. 常见问题排查

### 7.1 WebDAV 返回 401

检查：

- `keyId/keySecret` 是否填反。
- Secret 是否复制完整。
- WebDAV 凭证是否已撤销。
- WebDAV 凭证是否绑定了目标目录。

### 7.2 WebDAV 返回 403

检查：

- 当前操作是否超出绑定目录。
- 上传是否缺少新建权限。
- 覆盖、重命名是否缺少更新权限。
- 删除是否缺少删除权限。

### 7.3 S3 返回 AccessDenied

检查：

- S3 Access Key ID 和 Secret 是否正确。
- Region 是否与服务端配置一致。
- 客户端是否使用 path-style。
- bucket 是否为 `personal`、`apps` 或 `services`。
- 对象 key 是否落在凭证授权的目录前缀下。
- 操作是否具备对应权限。

### 7.4 S3 客户端看不到 bucket

Warehouse 会按凭证授权范围过滤 bucket。比如凭证授权 `/personal/backup`，`ListBuckets` 只会看到 `personal`；凭证授权 `/apps/demo`，只会看到 `apps`；凭证授权 `/services/reporting`，只会看到 `services`。

### 7.5 上传失败或中途断开

检查：

- 当前用户额度是否足够。
- 反向代理是否限制请求体大小或上传超时。
- S3 Endpoint 是否指向 active 节点。
- 客户端是否因为断点续传、覆盖或临时文件操作需要额外权限。

### 7.6 删除后额度没有下降

如果是 Web 页面或 WebDAV 删除，文件会进入回收站，仍然占用额度。需要在回收站永久删除或清空回收站后，额度才会下降。

如果是 S3 删除，删除是永久删除，正常情况下会释放对应存储占用。

## 8. 安全建议

- 不要把账号密码配置到自动化脚本中，改用 WebDAV 或 S3 凭证。
- 每个客户端、脚本或集成任务使用独立凭证。
- 每个凭证只授权一个明确目录前缀。
- Secret 只保存到密码管理器、CI Secret 或系统凭证存储中。
- 定期轮换：新建新凭证，客户端切换成功后撤销旧凭证。
- 已撤销且不再需要展示的凭证可以删除。
- 不要在日志、截图、Issue、PR 或聊天记录中粘贴 Secret。
